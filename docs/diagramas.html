5. Diagrama de secuencia: autenticación JWT

Inicio de sesión y posterior acceso a un endpoint protegido (ejemplo: crear una cita).

sequenceDiagram
  autonumber
  actor U as Usuario
  participant AC as AuthController
  participant AS as AuthService
  participant AM as AuthenticationManager
  participant UR as UserRepository
  participant JS as JwtService
  participant TR as TokenRepository
  participant F as JwtAuthenticationFilter
  participant APC as AppointmentController
  participant APS as AppointmentService
  participant DB as MySQL

  U->>AC: POST /auth/login {email, password}
  AC->>AS: authenticate(AuthRequest)
  AS->>AM: authenticate(email, password)
  AM->>UR: findByEmail(email)
  UR->>DB: SELECT users
  DB-->>UR: User + roles
  AM-->>AS: autenticado (BCrypt OK)
  AS->>JS: generateToken(user) / generateRefreshToken(user)
  JS-->>AS: access + refresh token
  AS->>TR: revocar tokens previos y guardar Token
  TR->>DB: INSERT/UPDATE token
  AS-->>AC: TokenResponse
  AC-->>U: 200 {accessToken, refreshToken}

  U->>F: POST /api/v1/appointments (Authorization: Bearer JWT)
  F->>JS: extractUsername / isTokenValid
  F->>TR: token no revocado ni expirado
  F->>F: SecurityContextHolder.setAuthentication()
  F->>APC: petición autorizada según rol/permiso
  APC->>APS: create(CreateAppointmentDto)
  APS->>DB: valida paciente, doctor y guarda Appointment
  DB-->>APS: Appointment
  APS-->>APC: AppointmentResponseDto
  APC-->>U: 201 Created
